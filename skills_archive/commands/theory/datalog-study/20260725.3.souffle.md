# Souffle: Datalog compiled to parallel C++

## 1. Thesis

Souffle (Scholz, Jordan, Subotic, et al., Oracle Labs / University of Sydney) compiles a Datalog
program AHEAD OF TIME into specialized, typed C++ that runs a parallel semi-naive fixpoint over
in-memory B-tree/trie data structures, or interprets the same IR when a compiler isn't wanted.
It trades interactivity (no live database, no incremental retraction, one shot per invocation)
for raw throughput on whole-program static analysis: points-to, taint, security lint, at
million/billion-tuple scale. It is the field's throughput reference point, not its reactivity
reference point — that split is exactly where sprefa's `v6/dl` diverges.

## 2. Surface + engine, one real sample each

| Concept | Sample |
|---|---|
| `.decl` + types | `.decl edge(x:number, y:number)` |
| `.input` / `.output` | `.input edge` / `.output path` |
| recursive rule | `path(x, y) :- path(x, z), edge(z, y).` |
| aggregate (`count`) | `B(s, c) :- W(s), c = count : { C(s, _) }.` |
| aggregate (`sum`) | `S(n) :- n = sum y : Prime(y).` |
| aggregate (`min`) | `B(z) :- z = min x+y : { A(x), A(y), C(y) }.` |
| aggregate (`max`) | `B(y) :- y = max z : A("A", z).` |
| stratified negation | `CanRenovate(person, building) :- Owner(person, building), !Heritage(building).` |
| subsumption (`<=`) | `min_distance(node, d1) <= min_distance(node, d2) :- d1 <= d2.` |
| choice-domain | `.decl st(v:symbol, u:symbol) choice-domain u` |
| component | `.comp MyComponent { .decl TheAnswer(x:number) TheAnswer(42). }` / `.init myInstance1 = MyComponent` |

Types are declared per column (`number`, `symbol`, or a user `.type`); `.decl` is a type
signature, not a storage hint — Souffle's compiler picks the storage (B-tree, brie, direct-index)
per relation from usage, not from syntax.

Stratified negation requires the negated atom's stratum to fully finish before the referencing
rule fires — same requirement sprefa's engine enforces via `src/engine/strata.rs`.

`choice-domain` declares a functional dependency directly in the relation head: at most one row
per choice-domain key survives, chosen implementation-defined-first. It has no sprefa analogue —
dl has no head-level dependency/uniqueness constraint; a `choice-domain`-shaped rule in dl would
need dedup at the query layer.

## 3. Three real sample programs

**(a) Reachability — the canonical Souffle "hello world":**

```datalog
// Transitive closure over a directed edge relation, read from edge.facts.
.decl edge(x:number, y:number)
.input edge

.decl path(x:number, y:number)
.output path

path(x, y) :- edge(x, y).
path(x, y) :- path(x, z), edge(z, y).
```

**(b) Aggregate — count of successors per node:**

```datalog
// out_degree(node, count) — one aggregate row per grouping var (node).
.decl edge(x:number, y:number)
.input edge
.decl out_degree(node:number, deg:number)
.output out_degree

out_degree(node, deg) :- edge(node, _), deg = count : { edge(node, _) }.
```

**(c) Subsumption — keep only the shortest distance per node, dominated rows deleted:**

```datalog
// min_distance(node, dist): a shorter dist for the same node subsumes (deletes) a longer one.
.decl edge(x:number, y:number, w:number)
.input edge
.decl min_distance(node:number, dist:number)
.output min_distance

min_distance(y, w)      :- edge(_, y, w).
min_distance(y, d1 + w) :- min_distance(x, d1), edge(x, y, w).
min_distance(node, d1) <= min_distance(node, d2) :- d1 <= d2.
```

The subsumption line is not a filter on the output — it retracts the dominated tuple from the
relation DURING evaluation, so the recursive rule above it never re-derives paths through an
already-beaten distance. This is Souffle's substitute for a priority queue inside a purely
declarative fixpoint.

## 4. Engine internals that matter to sprefa

| Souffle mechanism | What it does | sprefa mapping |
|---|---|---|
| Semi-naive evaluation | Per stratum, seed a delta table from the non-recursive rules, then each round re-fire every recursive rule with exactly one body atom bound to the prior round's delta, merge new rows, repeat until delta is empty. | `v6/sprefa-store/js/src/lower/lowerSql.ts:114-176` — same shape: `_dl_delta_<rel>` tables per member rel, `insertNewRows` seeds them, the recursive loop overrides one body position per round (`deltaOf`/`nextDeltaOf`), drains until empty. Souffle runs this loop compiled and parallel in C++; sprefa runs it as generated SQL against SQLite, one query per round. |
| Magic sets / demand transformation | Static rewrite: specialize a rule set to the actual bound arguments of a query (adornment: `a_fbf` = free/bound/free), generating `magic` predicates that push the query's constants down through the rule bodies so irrelevant tuples are never derived. Enabled per-relation with `.decl foo(...) magic` / disabled with `no_magic`. | `v6/dl/src/0_ast_bridge.ts` — the `h?(inputs.., outputs..)` probe operator mints a `__req_h` demand rule (columns = input cols + salts) and an `__resp_h` EDB rel (0_ast_bridge.ts:6-33, 641-651, 949-957). Both are demand-side rewrites shaped by adornment (which args are bound going in, which come back out) — but sprefa's demand key is a runtime effect-call boundary (async host calls, salted per witness), not a static specialization of a whole recursive rule set over EDB constants. Souffle's magic sets shrink fixpoint search space; sprefa's `__req`/`__resp` schedules and dedupes side-effecting calls. Related shape, different job. |
| Strata scheduling | Stratified negation/aggregation partitions rules into strata by a dependency graph; strata run in topological order, each to full fixpoint before the next starts. | `src/engine/strata.rs` — same requirement, same partition-then-order shape, enforced at plan time in the Rust engine. |
| Index/data-structure selection | Per relation, the Souffle compiler picks a B-tree (ordered, range-query-friendly) or brie (trie, dense integer domains) or a direct/hash index, chosen from the rule set's usage patterns — a compile-time decision baked into generated C++, no runtime index bloat possible. | `src/engine/declare.rs:625 create_auto_indexes` — sprefa's analogous problem, solved at RUNTIME against SQLite: infer needed indexes from join/filter shape and materialize `CREATE INDEX` statements. Landed direction 5 (2026-07-19, branch `index-audit`) cut 771 -> 262 `idx_` tables, -117.7MB, by adding planner-honest demand filters (PK-prefix on rowid tables, tiny-rel floor, constant-column skip) — the same selection problem Souffle solves once at compile time, sprefa re-solves per schema against a general-purpose row store that autoindex will happily overprovision if left unchecked. |

## 5. Why this repo cares

- Souffle's ceiling is the real ceiling: compiled C++ over B-tree/brie beats interpreted SQL
  per-round query dispatch by a wide, unmeasured-here margin — sprefa's semi-naive loop pays
  SQLite's per-statement overhead every round that Souffle's generated loop does not.
- Magic sets are a genuine gap: sprefa has no static demand-driven specialization of a recursive
  rule set against bound query constants — only the effect-call `__req`/`__resp` probe rewrite,
  which is demand-shaped but scoped to host calls, not general fixpoint pruning.
- Index selection is the direct kin of `create_auto_indexes` — Souffle picks the data structure
  once at compile time from static usage; sprefa infers indexes at runtime against a store that
  didn't design its physical layout around the rule set, hence the ongoing storage-diet arc.
- Subsumption (`<=`) has no sprefa equivalent: dominance-based tuple deletion inside a fixpoint
  round is a pattern dl would need to hand-roll as a derived rule plus an explicit delete pass —
  worth flagging if a shortest-path-shaped rule ever lands in a `.dl` program.
- What sprefa gets right that Souffle omits entirely: Souffle is batch — one shot, no take-backs,
  no live retraction. `v6/dl`'s whole reason to exist is reactive incremental maintenance under
  file-change retraction, which Souffle's model does not attempt to solve at all.
- `choice-domain` is a head-level functional-dependency constraint Souffle has and dl lacks;
  worth naming explicitly rather than silently reimplementing as an ad hoc dedup rule if the need
  ever comes up.
