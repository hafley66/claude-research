# Session: dioxus-browser-ext-desktop-devtool

## Goal
Research and document Dioxus ecosystem for building browser extensions and desktop devtool apps, replacing Electron with lightweight WASM/WebView alternatives.

## Current State
Six skills created or updated this session. All committed across two commits (bcabc34, eaed369). One uncommitted change: starter kits section added to dioxus-ecosystem.

## Problem/Context
User has an invested Chrome extension for work where the devtools panel was popped into an Electron app. Shipping a 400MB Electron zip is unacceptable. Target: ~5MB binary via Dioxus desktop (Wry/WebView) or a Chrome extension with WASM popups. The tool connects to existing apps via WebSocket -- no fullstack/SSR, no HTTP framework replacement. Architecture is coroutine-based: WS messages flow through signals to UI.

## Solution/Approach
- Chrome extension: separate WASM crates per context (popup, background, content, options), wasm-pack build, chrome.runtime ports for IPC, gloo-net WebSocket in background
- Desktop (Wry): same Dioxus UI code, tokio-tungstenite for WS, filesystem for storage, native webview rendering
- Shared workspace: common/ (types), ui/ (platform-agnostic components), extension/ (chrome wiring), desktop/ (Wry wiring)
- RxJS patterns replaced by: Signal (BehaviorSubject), use_coroutine (Subject/Epic), use_memo (combineLatest/map), use_resource (switchMap)
- Time-based operators (debounce, throttle) require manual coroutine implementations with futures::select + timer drain loops

## Key Insights
- Dioxus extensions use wasm-pack, NOT dx CLI. Each context is a separate .wasm binary.
- `'wasm-unsafe-eval'` mandatory in extension CSP for WASM
- web-extensions-sys is Chrome-only, Firefox needs raw wasm-bindgen to browser.* namespace
- Service workers can be killed by Chrome when idle -- WS connections drop, need reconnection logic
- gloo crates (gloo-net, gloo-storage, gloo-timers) are the idiomatic web-sys wrappers
- No react-use/VueUse equivalent exists -- ecosystem is fragmented micro-crates. Hand-rolling from web_sys more reliable.
- Closure::forget() is the universal tax for bridging JS callbacks into Rust
- async closures not stable yet, so move || async move {} double-wrapper is unavoidable for use_future
- dioxus-query v0.9.2 has interval + window focus refetch but fullstack integration still WIP
- dioxus-forms (Dec 2025) + vld (Mar 2026) are the first real React Hook Form + Zod equivalents, both brand new
- No kitchen-sink admin starter exists in Dioxus ecosystem
