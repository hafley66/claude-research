# Flix: Datalog constraints as first-class values in a typed functional language

Source pair: Madsen, Yee & Lhoták, *From Datalog to Flix: A Declarative Language
for Fixed Points on Lattices*, PLDI 2016[^pldi16]; Madsen & Lhoták, *Fixpoints
for the Masses: Programming with First-Class Datalog Constraints*, OOPSLA
2020[^oopsla20]. All syntax below is verified against current
doc.flix.dev[^fixpoints][^lattice][^stratneg][^forllms] and the flix/flix
example corpus[^topsort], not the 2016 paper's syntax — current Flix (0.68+)
dropped the paper's standalone `rel`/`lat` declaration keywords in favor of
inferred, row-polymorphic predicate types[^forllms].

## 1. Thesis

Flix is a general-purpose, ML-family, statically-typed functional language on
the JVM in which Datalog constraint sets are FIRST-CLASS VALUES: a program can
build one (`#{ ... }`), pass it to a function, compose it with another with
`<+>`, and only later `solve` or `query` it — the same way any other value
flows through the language. Plain relational facts are the degenerate case of
a more general fact shape: a LATTICE-VALUED fact, where two facts sharing a key
don't just coexist as two rows but MERGE via a declared least-upper-bound
function, so Datalog's fixed point generalizes from set-union reachability to
any monotone dataflow analysis (constant propagation, sign analysis, shortest
paths) without leaving the relational rule syntax.

## 2. Core constructs

| Concept | Real sample |
|---|---|
| predicate (inferred — no `rel` keyword in current Flix) | `let rules = #{ Path(x, y) :- Edge(x, y). Path(x, z) :- Path(x, y), Edge(y, z). };` |
| lattice predicate (`;` marks lattice semantics on the last arg) | `LocalVar(r; sum(v1, v2)) :- AddStm(r, x, y), LocalVar(x; v1), LocalVar(y; v2).` |
| lattice bottom | `instance LowerBound[Sign] { pub def minValue(): Sign = Bot }` |
| lattice join (lub) | `instance JoinLattice[Sign] { pub def leastUpperBound(x: Sign, y: Sign): Sign = ... }` |
| fixpoint, results kept as a constraint value | `let m = solve f1, r1 project ColorPath;` |
| fixpoint, results extracted to a host value | `let paths = query edges, rules select true from Path(src, dst);` |
| host data injected as facts | `let edges = inject s into Edge/2;` (arity is mandatory: `Pred/N`) |
| stratified negation | `not StarringIn(title, name)` |
| first-class constraint-set composition | `#{ Edge(n, n * 2). Edge(n, n * 2 + 1). } <+> genEdges(n - 1)` |

The 2016 paper's `rel Edge(x: Var, y: Var)` / `lat LocalVar(x: Var, v: Sign)`
top-level declarations are gone from current Flix; a predicate's type is now
inferred from the row-polymorphic signature of the function that returns it
(`#{ ParentOf(String, String) | r }`, section 3c below) or from its use inside
a `#{ ... }` literal[^forllms]. The `;` before a predicate's last argument is
what current Flix uses in place of the old `lat` keyword to mark that argument
as lattice-valued rather than a plain relational column[^lattice].

## 3. Three sample programs

**(a) Reachability / transitive closure** — the canonical case, a function
wrapping a two-rule fixpoint[^fixpoints]:

```flix
def isConnected(s: Set[(Int32, Int32)], src: Int32, dst: Int32): Bool =
    let rules = #{
        Path(x, y) :- Edge(x, y).
        Path(x, z) :- Path(x, y), Edge(y, z).      // recursive rule, plain set semantics
    };
    let edges = inject s into Edge/2;
    let paths = query edges, rules select true from Path(src, dst);
    not (paths |> Vector.isEmpty)
```

**(b) A lattice-valued analysis (sign propagation)** — facts on the same key
merge by the declared `leastUpperBound`, not by accumulating rows[^lattice]:

```flix
instance JoinLattice[Sign] {
    pub def leastUpperBound(x: Sign, y: Sign): Sign = match (x, y) {
        case (Bot, _)   => y
        case (_, Bot)   => x
        case (Neg, Neg) => Neg
        case (Zer, Zer) => Zer
        case (Pos, Pos) => Pos
        case _          => Top                     // conflicting signs widen to Top, not an error
    }
}
let p = #{
    LocalVar("x"; Pos).  LocalVar("x"; Neg).        // same key "x" -> lub'd to LocalVar("x"; Top), not two rows
    LocalVar(r; sum(v1, v2)) :- AddStm(r, x, y), LocalVar(x; v1), LocalVar(y; v2).
};
```

**(c) First-class constraints** — a function returning a Datalog program
VALUE, composed with `<+>`, solved later — trimmed from flix/flix's own
`examples/datalog/topsort.flix`[^topsort]:

```flix
def genEdges(n: Int32): #{ Edge(Int32, Int32) | _ } =              // returns a constraint-set VALUE
    if (n <= 0) #{} else #{ Edge(n, n * 2). Edge(n, n * 2 + 1). } <+> genEdges(n - 1)

def main(): Unit \ IO =
    let edges = genEdges(20);
    let lp = #{
        Vertex(v) :- Edge(v, _).
        IsBefore(x, y) :- Edge(x, y).
        IsBefore(x, y) :- IsBefore(x, z), IsBefore(z, y).
    };
    query lp <+> edges select (x, y) from IsBefore(x, y) |> println   // <+> unions two values at solve time
```

## 4. Stratified negation

```flix
let rule = #{
    MovieWithoutDirector(title) :-
        Movie(title),
        DirectedBy(title, name),
        not StarringIn(title, name).                // negated body atom
};
```

Flix's own wording: "a program must not have recursive dependencies on which
there is use of negation. If there is, the Flix compiler rejects the
program."[^stratneg] No compile-error text is published on that page — the
check is a compiler-internal stratifiability analysis, not a documented
diagnostic string.

sprefa's v6 `rulegraph.ts` is the same check, made explicit: `buildRuleGraph`
→ `scc` (Tarjan) → `stratify` (condense + topo-sort)[^rulegraph2-19]. A
`!rel(args)` body predicate is still an ordinary dependency edge (the negated
rel must evaluate first) but is ALSO recorded in `Graph.negAdj` as a "forcing
edge"[^rulegraph14-19]. `stratify()` checks every `negAdj` edge before doing
any condensation work and throws `NonStratifiableError` the moment a negative
edge's two endpoints share an SCC[^rulegraph189-208], with message wording
pinned to match v5's Rust engine (`src/typecheck.rs:1201`, the `not-stratified`
diagnostic): `` relation `{rel}` is aggregated or negated inside a recursive
cycle with `{cycleWith}` ``[^rulegraph164-181]. Same requirement as Flix's
stratifiability rule, enforced at a different point in the pipeline: Flix
rejects it as part of compiling a typed program; sprefa rejects it post hoc,
as a graph-theoretic property (shared SCC membership) computed over the
already-parsed rule set.

## 5. Why this repo cares

- **Lattice facts generalize dl's `key(...) merge(...)` today** (v5,
  `src/ast.rs:103-122`): `MergeFn::MaxBy(col)` / `MergeFn::MinBy(col)` pick a
  whole winning ROW by a priority column on key conflict — explicitly "no
  Galois cross-row mixing" per the code comment. Flix's `JoinLattice` computes
  a NEW value from two different inputs (`Neg ⊔ Pos = Top`, a value neither
  side had). dl's two merge functions are a much narrower special case
  (row-selection) of the general lattice-join Flix exposes as an arbitrary
  type-class instance — worth naming as a real semantic gap, not asserting dl
  should grow a general lattice mechanism.
- **`MergeFn::MinBy` already IS Flix's shortest-path `Down[Int32]` pattern**
  (`src/ast.rs:117-121`'s own comment names "the shortest-path lattice"), just
  without the general `JoinLattice` machinery behind it — same idea landed
  independently, narrower.
- **v6/dl has not ported this yet.** `key`/`merge` lives only in the v5 Rust
  engine (`src/ast.rs`, `src/lower.rs:699`, `src/engine/typed_plan.rs`,
  `src/engine/derive.rs`, `src/engine/declare.rs`); a repo-wide grep of
  `v6/sprefa-store/js/src` turns up no `MaxBy`/`MinBy`/`merge(` hits outside
  an unrelated rxjs `merge()` call. Flix's fuller lattice model is a design
  reference for that porting decision, not evidence it's already handled.
- **First-class composable constraints have no dl analogue.** A `.dl` file is
  parsed once as a static program; there's no dl-level function that BUILDS
  and RETURNS a rule-set value for another program to `<+>`-compose, the way
  `genEdges` does. Flagging the gap, not asserting the fix — no build-vs-buy
  analysis has been run on whether dl should grow this.
- **Stratified negation parity is exact in shape, not in mechanism.** Flix
  checks stratifiability as part of type-checking a general-purpose program;
  sprefa's `rulegraph.ts` checks it as a pure post-hoc graph property (Tarjan
  SCC + negative-edge intersection) over an already-parsed `.dl` program — same
  requirement Datafun's `fix` side-condition states as a type theorem (see the
  sibling `datafun.md` chapter), enforced at three different points in three
  different pipelines.
- **The overall shape is inverted.** Flix is a full typed FP language with
  Datalog as one embedded feature; dl is Datalog-first with SQL as its only
  "host," and no general-purpose function layer around rule sets. That
  asymmetry is worth stating plainly rather than treating Flix as an implicit
  roadmap for what dl should become.
